# Deployment

## Local development

```bash
cd backend
node server.js
```

Backend listens on `http://localhost:8080`. Health check: `curl http://localhost:8080/health`.

## Docker

```bash
docker build -t daycare-backend .
docker run --rm -p 8080:8080 --env-file backend/.env daycare-backend
```

The image uses `npm ci --omit=dev`, so dev dependencies (jest, sqlite3, supertest) are excluded from the production image.

## Publishing to ECR

```bash
REPO_URI="029862721591.dkr.ecr.eu-west-1.amazonaws.com/daycare-backend"

aws ecr get-login-password --region eu-west-1 | \
  docker login --username AWS --password-stdin "$REPO_URI"

docker tag daycare-backend:latest "${REPO_URI}:latest"
docker push "${REPO_URI}:latest"
```

## Frontend deployment

```bash
cd frontend
aws s3 cp index.html s3://daycare-frontend-huiseon/index.html
aws s3 cp app.js     s3://daycare-frontend-huiseon/app.js

aws cloudfront create-invalidation \
  --distribution-id E2ZISHE6S9U5HN \
  --paths "/*"
```

## Deployment decisions

### Sprint 4: Elastic Beanstalk challenge

During Sprint 4, the backend was prepared for deployment to AWS Elastic Beanstalk:

**What was completed:**

- Backend code optimised for EB
- Dependencies configured (Express, Sequelize, AWS SDK)
- `.ebextensions/nodejs.config` created
- EB environment created, EC2 instance provisioned

**Issue encountered:**

```
Error: connect ETIMEDOUT 172.31.17.127:5432
```

The EB instance could not reach RDS.

### Options evaluated

| Option | Cost | Time | Complexity | Decision |
|--------|------|------|------------|----------|
| A: Recreate EB in RDS subnet | $0 | 1 hour | Medium | Risky |
| B: Add load balancer for HTTPS | $16–20/mo | 2 hours | High | Too expensive |
| C: Local backend + CloudFront frontend | $0.70/mo | 0 hours | Low | ✅ Chosen at submission |
| D: Lambda + API Gateway | $1–5/mo | 4 hours | Very High | Over-engineered |

### Why Option C was chosen at submission

- **Cost:** RDS only, ~$0.70/month. Option B would add $16–20/month.
- **Time:** Zero additional setup. Focus on the final report.
- **Validation:** Proved the system works end-to-end against RDS.

## Post-sprint work (October 2026)

After the initial submission, I completed the deployment work:

- **Containerized the backend** — production Dockerfile using `npm ci --omit=dev`, no native compilation, image size ~233 MB.
- **Published the image to Amazon ECR** — `029862721591.dkr.ecr.eu-west-1.amazonaws.com/daycare-backend:latest`.
- **Verified the container against RDS** — `/health` returns Connected; Cognito login issues a JWT; authenticated routes work.
- **Fixed a data consistency issue** — an older migration script created a duplicate `attendances` table. Renamed the stale table to `attendances_old` and updated the script.
- **Prepared for ECS Express Mode** — App Runner stopped accepting new customers in April 2026. The image is deployable to ECS Express Mode as-is.

## Data provenance

The RDS database contains two datasets:

1. **Migrated data** — 11 children and 3 attendance records from the original SQLite version. The 3 attendance records are preserved in `attendances_old`.
2. **Seeded demo data** — 25 children and 84 attendance records generated by `seed-25-children.js` and `seed-week-attendance.js`. Used to populate the ECCE report with realistic variation.

Both datasets serve different purposes: the migrated data proves the migration worked; the seeded data demonstrates the reporting feature.
